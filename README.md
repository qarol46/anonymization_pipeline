# Industrial Anonymization Pipeline

Промышленный пайплайн анонимизации русскоязычных корпоративных документов на базе **Microsoft Presidio**.

Разработан для повторной анонимизации корпуса документов ритейл-компании с учётом раздельной типизации сущностей, сохранения ролей, подразделений и дат вступления документов в силу.

---

## 🎯 Возможности

- **Раздельная типизация сущностей** — `PERSON_NNN`, `EXTORG_NNN`, `SITE_NNN`, `CONTACT_NNN`
- **Rule-based контекстный классификатор** — различает внешние и внутренние организации
- **Определение ролей сотрудников** — руководитель / подчинённый / ответственный
- **Сохранение дат** — даты вступления в силу документов не обезличиваются
- **Сохранение подразделений и должностей** — департаменты, отделы, роли остаются в открытом виде
- **Обработка имён файлов** — отдельный проход с проверкой на остаточные ФИО
- **Контрольный проход** — автоматическая проверка по 9 критериям приёмки

## 🚀 Установка

### 1. Клонируйте репозиторий

git clone https://github.com/ВАШ_ЛОГИН/retail-anonymization-pipeline.git
cd retail-anonymization-pipeline

### 2. Создайте виртуальное окружение

python -m venv venv
source venv/bin/activate  # macOS / Linux
# или venv\Scripts\activate  # Windows

### 3. Установите зависимости

pip install --upgrade pip
pip install -r requirements.txt

### 4. Скачайте NLP-модели spaCy

python -m spacy download ru_core_news_sm
python -m spacy download en_core_web_sm

💡 Для более точного распознавания можно использовать модели `lg` (large):

python -m spacy download ru_core_news_lg
python -m spacy download en_core_web_lg

Не забудьте обновить `engines/analyzer.py` на соответствующие названия моделей.

## ⚙️ Использование

### Запуск пайплайна

python main.py

### Что произойдёт

1. **Инициализация** — загрузка моделей spaCy и настройка распознавателей
2. **Обработка корпуса** — каждый документ из `input_corpus/` анализируется и анонимизируется
3. **Обработка имён файлов** — проверка и очистка имён файлов от остаточных ФИО
4. **Контрольная проверка** — валидация результата по 9 критериям приёмки
5. **Сохранение результатов** — карта соответствий и протокол обработки

### Результаты

После завершения в папке `output/` появятся:

| Файл | Описание |
|------|----------|
| `anonymized_corpus/` | Обезличенные документы |
| `entity_mapping.json` | Карта соответствий `плейсхолдер → тип сущности` |
| `processing_log.json` | Протокол обработки со статистикой |

### Пример `entity_mapping.json`

  "counters": {

## 🏗 Архитектура

Пайплайн состоит из 5 уровней:

1. **Обнаружение (Discovery)** — Presidio Analyzer + кастомные распознаватели
2. **Классификация (Classification)** — Rule-based контекстный классификатор, различение внешних/внутренних организаций
3. **Анализ ролей (Role Analysis)** — определение руководитель / подчинённый / ответственный
4. **Анонимизация (Anonymization)** — TypedPseudonymizer с раздельной типизацией
5. **Валидация (Validation)** — контрольный проход по критериям приёмки

---

## 📋 Правила обработки сущностей

| Категория | Действие | Формат |
|-----------|----------|--------|
| Физические лица (ФИО, инициалы) | Обезличить | `PERSON_NNN` |
| Внешние организации (поставщики, подрядчики) | Обезличить | `EXTORG_NNN` |
| Собственные подразделения | **Сохранить** | — |
| Должности и роли | **Сохранить** | — |
| Наименования документов, процессов | **Сохранить** | — |
| Адреса и номера объектов | Обезличить | `SITE_NNN` |
| Регионы и федеральные округа | **Сохранить** | — |
| Даты вступления в силу | **Сохранить** | — |
| Контактные данные (телефоны, email) | Обезличить | `CONTACT_NNN` |
| Идентификаторы (СНИЛС, ИНН, паспорта) | Обезличить | `CONTACT_NNN` |

## ✅ Критерии приёмки

Пайплайн автоматически проверяет результат по 9 критериям:

1. **Остаточные ФИО** — 0 вхождений
2. **Контактные данные** — 0 вхождений
3. **Идентификаторы** — 0 вхождений
4. **Соответствие плейсхолдера типу** — ≥95% вхождений PERSON в контексте физического лица
5. **Сохранность дат** — доля документов с читаемой датой вступления в силу не ниже исходной
6. **Сохранность ролей** — ≥1188 секций с читаемыми наименованиями ролей
7. **Сохранность подразделений** — наименования в открытом виде
8. **Разделители** — 0 склеек плейсхолдера со словом
9. **Карта типов** — покрывает 100% использованных плейсхолдеров

## 🔧 Расширение и кастомизация

### Добавление нового распознавателя

Создайте файл в `recognizers/` по аналогии с существующими и добавьте его в `engines/analyzer.py`:

from recognizers.my_custom_recognizer import MyCustomRecognizer
registry.add_recognizer(MyCustomRecognizer())

### Добавление нового типа сущности

Отредактируйте `config/settings.py`:

ENTITY_RULES = {
    "MY_NEW_ENTITY": {"action": "anonymize", "placeholder": "MYTYPE"},
    # ...
}

### Настройка контекстного классификатора

Добавьте ключевые слова в `config/settings.py`:

INTERNAL_ORG_KEYWORDS = [
    "департамент", "отдел", "ваше_новое_слово",
    # ...
]
